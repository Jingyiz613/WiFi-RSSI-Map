## 任务概述

基于 MiniAuto Pro 小车构建室内 Wi-Fi RSSI 网格采集平台，在保留手机遥控能力的基础上，实现信号采集、覆盖可视化，以及“移动—停车稳定—采样—保存—下一点”的车载任务程序，为后续室内无线信号分布分析提供数据。

当前阶段：已取得一组完整的人工逐点采集数据，完成可配置定时采样和循环路线程序；最新 v10 已编译，尚未烧录和完成实车自动采集验收。建议团队任务状态设为 **进行中 / 待现场验证**。

## 实测数据结果

采集日期为 2026-11-03，路由器位于 P22。7×9 网格共 63 个点，排除路由器所在点，实际采集 62 个点，每点 10 次，共 620 条有效 RSSI 样本。

| 指标 | 结果 |
|---|---:|
| 已测点位数 | 62 |
| 有效样本数 | 620 |
| 每点有效样本数 | 10 |
| 全部样本 RSSI 范围 | −51～−13 dBm |
| 全部样本 RSSI 均值 | −33.90 dBm |
| 全部样本 RSSI 中位数 | −35 dBm |
| 点位中位数最低 | P29：−50 dBm |
| 点位中位数最高 | P12：−14.5 dBm |

RSSI 数值越接近 0，信号越强。本组结果证明采集与数据处理链路可用，但只覆盖一个路由器位置和当时的实验条件；不能据此宣称自动驾驶完成、家具影响已得到对照验证，或模型具备跨房间泛化能力。

## v10 自动采集程序

任务流程：启动延时 → 起点采样 → 移动 → 停车稳定 → 按间隔采样并保存 → 下一点 → 按规划返回起点 → 记录本轮完成 → 等待 → 下一轮。

| 参数 | 默认设置 | 可配置范围 |
|---|---:|---|
| 启动延时 | 0 秒 | 0～86400 秒 |
| 停车稳定时间 | 3 秒 | 0～300 秒 |
| 样本间隔 | 1 秒 | 0.2～60 秒 |
| 每点采样次数 | 10 次 | 1～100 次 |
| 任务轮次 | 2 轮 | 1～10000 轮；0 为持续循环 |
| 两轮间隔 | 60 秒 | 0～86400 秒 |

任务启动后，正常的测点切换与轮次切换无需人工逐次确认，定时器在 ESP32 上运行，不依赖外网或电脑持续发送任务心跳。程序使用相对时间，不是按每天某时刻启动的日历任务。

每条采样记录写入 LittleFS 并执行 flush，CSV 包含轮次、上电毫秒、点号、样本序号、RSSI、接入点信息及名义位置来源；另外记录每点和每轮完成事件。存储容量有限，持续循环在人工停止、存储不足或保护故障时结束；不会自动覆盖旧数据。重启保持停车，不自动从未知位置续跑。

### 路线规划与超声波分工

- 先把固定柜、家具、路由器和电线的禁行范围加入地图，并考虑车身外廓与转弯余量，再生成路线。
- 超声波用于前方临时障碍防护：停车等待，障碍消失且读数稳定后按程序恢复；反馈异常仍会终止控制。
- 当前方案不具备 SLAM、自主识别全部家具或绕未知障碍重新规划的能力；前向超声波也不能可靠覆盖低矮电线和侧面障碍。
- 编码器提供的是名义位置，闭环路线计算通过不代表实车精确回到起点；多轮漂移需要实测。

## 当前现场问题与完成边界

最后留存的实车记录为 v9；v10 尚未烧录。此前运动诊断曾复现底盘方向反馈故障 `0x80`，一次参数修复未通过复测，已恢复原参数，根因尚未确认。

最后一次 v9 预检中，底盘电压为 8207 mV，四路编码器均为 0，底盘标志为 0，前向测距为 868 mm。随后因本地控制端口连接超时，20 cm 试验没有发出移动命令。因此该记录只能证明当次静态预检可读，不能认定直行、制动或超声波稳定性通过。

实验路由器没有外网不妨碍本地采样。电脑可保持 Wi-Fi 连接实验路由器，再由手机 USB 共享提供外网；需要现场核验电脑与小车的控制端口能互通。
