# 使用说明

## 零、如果你的被测 Wi-Fi 不能上网

本文档描述的是**在线模式**：电脑必须连上被测 Wi-Fi，才能通过 HTTP 控制小车。
如果那个网络不能上网，电脑一连上就会和 DeepWorks 断开。

这种情况请改用**离线模式**：电脑通过 USB 下发任务，之后拔线，小车自己跑完，
再插线取数据。电脑全程不需要连被测 Wi-Fi。

详见 [离线采集说明.md](离线采集说明.md)。

## 一、系统是怎么工作的

```
电脑（Python）                          小车（ESP32）
─────────────                          ─────────────
读串口拿控制密钥  ──USB──▶  SURVEY_KEY
规划蛇形路线
POST /survey/command ──WiFi──▶  电机走固定距离（编码器闭环）
GET /espectre/v1/wifi ◀──WiFi── 返回当前关联 AP 的 RSSI
写 CSV
```

关键点：**小车不自己规划路线**。电脑算好每一段走多远，逐段下发；小车只负责按编码器走完指定距离并回报状态。这样路线改动只改电脑端，不用重新烧录。

## 二、首次使用流程

### 第 1 步：装 Python 环境

```powershell
powershell -ExecutionPolicy Bypass -File tools\setup_env.ps1
```

### 关于命令里的 `tools\py.cmd`

下面所有 Python 命令都从**项目根目录**执行，用 `tools\py.cmd` 代替 `python`。
它会自动找到装了依赖的那个解释器，不用手动激活虚拟环境。

如果 PowerShell 提示"无法加载文件，因为在此系统上禁止运行脚本"，
在命令前加 `cmd /c` 即可，例如：

```powershell
cmd /c tools\py.cmd host\survey_cli.py --ap P68 --preview-image
```

### 第 2 步：烧录固件

**2.1 先认板子（不写入任何东西）**

用 USB 线连接小车和电脑，然后执行：

```powershell
powershell -ExecutionPolicy Bypass -File tools\flash.ps1 -Identify
```

脚本会自动找到串口，打印芯片型号、Flash 大小、MAC 地址，例如：

```
Chip  : ESP32-D0WD-V3 (revision v3.1)
Flash : 4MB
MAC   : a0:b7:65:xx:xx:xx
Board matches the prebuilt '-Chip esp32' firmware.
```

如果显示 `Mismatch`，说明你的板子不是 ESP32（比如是 ESP32-S3），
预编译固件烧不进去，需要先用 `tools\build.ps1` 重新编译。

**2.2 烧录**

```powershell
powershell -ExecutionPolicy Bypass -File tools\flash.ps1 -Backup
```

串口会自动识别，不用手填。如果有多个串口，脚本会列出让你选编号。

`-Backup` 会先把小车当前的 4 MB Flash 完整备份到 `backup/` 目录，出问题可以恢复。
输入 `FLASH` 确认后开始写入，整个过程约 30 秒。

> 脚本写入前会再读一次芯片型号，与固件不匹配会直接拒绝，不会烧坏。

> 如果你改了固件源码想重新编译，装好 arduino-cli 后执行 `tools\build.ps1`，
> 把 `firmware/build/` 里的 4 个 bin 复制到 `firmware/bin/`（文件名保持不变）。

### 第 3 步：配网

```powershell
tools\py.cmd host\provision_wifi.py --port COM8 --ssid 你的WiFi --password 你的密码
```

成功后会打印：

```
已连接：SSID=Xiaomi_2D1F_2.4G BSSID=... 信道=11 RSSI=-35 dBm IP=192.168.31.65
小车地址：192.168.31.65:62587
```

**把这个地址记下来**，第 4 步要填。配网信息存在小车 NVS 里，断电不丢，下次上电自动连。

### 第 4 步：标记家具和障碍（可选）

房间里有沙发、床、柜子这类不能压过去的家具时，先在界面上标出来，路线会自动绕开。

1. 点选「家具」模式
2. **按住鼠标左键拖动**，拉出一个矩形把家具框住，松手
3. 弹窗里输入名字（沙发、床、书桌……），确定

尺寸不必对齐格子。程序按厘米记录家具的真实位置：2.13 m 宽的沙发就画 2.13 m，
不会被迫占满 3 个格子，也不会因为压到格子边缘就废掉一整格。

**怎么判定哪些格子不能用：**

格子中心到家具矩形的距离小于「安全间距」就判为不可用，默认 10 cm。
所以只有真正挡住采样点的格子才会被排除，家具边缘蹭到格子不算。

安全间距在右侧「房间与安全间距」里改：

| 数值 | 适用 |
|---|---|
| 8 cm | 车窄、想多采几个点 |
| 10 cm | 默认，车体半宽 + 少量余量 |
| 15 cm | 保守，地面不平或家具边缘不规则 |

要点：

- 家具必须是矩形。L 形沙发拆成两块分别标，斜放的家具把外接矩形全框进去
- 路由器和起点不能被家具盖住，否则拖动松手时直接拒绝
- 家具之间至少留 1 格通道，否则小车开不进去；界面会显示红色警告
- 双击清单里的家具可以改名；选中后点「删除选中」可以删掉
- 单个格子点错了，用「单格障碍」模式补，再点一次取消
- 标错了点「清空家具」重来

标完直接关窗口，布局会自动存到 `layout.json`，下次打开自动恢复。
换房间或换布置时，改完自动覆盖；想留多份就点「保存布局」另存一份。

**布局文件格式**（想手改或脚本生成时参考）：

```json
{
  "version": 2,
  "room": {"rows": 7, "columns": 9, "width_m": 8.23, "height_m": 6.95},
  "clearance_m": 0.10,
  "ap": "P68",
  "start": "P11",
  "furniture": [
    {"name": "沙发", "x1": 0.30, "y1": 3.00, "x2": 2.50, "y2": 3.90}
  ],
  "manual_blocked": ["P44"]
}
```

`x1/y1` 是左上角，`x2/y2` 是右下角，单位米，原点在房间左上角。
旧版按格子存的布局（`row1/col1/row2/col2`）会自动换算，不用手动迁移。

### 第 5 步：首次校准（必做）

编码器"走了一格"不等于"车身真的移动了一格"。麦轮横移打滑更明显。必须实测。

**方向测试：**

1. 把小车放在空地，车头朝前
2. 在界面里填好串口和地址
3. 命令行执行 20 cm 单轴测试：

```powershell
tools\py.cmd host\survey_cli.py --run --test-axis x --test-distance 0.2 --target 192.168.31.65:62587 --port COM8
```

> 目前版本的方向/距离测试通过 `survey_cli.py` 的参数控制；如果界面里没有对应按钮，用命令行更直接。

**距离测试：**

1. 地面上贴一条起点线，车头对准
2. 命令走一格（横向 0.9144 m / 纵向 0.9929 m）
3. 用卷尺量实际位移
4. 计算补偿系数：

```
新系数 = 原系数 × 目标距离 ÷ 实测距离
```

例如命令走 0.9144 m，实际只走了 0.85 m，横向系数应为 `1.0 × 0.9144 ÷ 0.85 ≈ 1.076`。

5. 把系数填回界面「X 校准 / Y 校准」。

**判断标准：** 如果车头方向不对、明显跑偏或每次距离差异很大，先检查轮子是否打滑、电池是否充足、地面是否平整，不要带着问题跑整组。

### 第 6 步：正式开始采集

1. 双击 `启动控制台.bat`
2. 设置行数/列数/房间宽高（默认 7×9、8.23×6.95 m，与你的历史数据一致）
3. 「点击模式」选 **路由器**，点路由器所在格子
   - 也可以直接输入 `P68`
   - 或者输入米制坐标 `3.2,1.5`（房间左上角为原点，x 向右、y 向下）
4. 需要的话标记障碍格（桌子、柜子、不能压的线）
5. 点「① 生成路线预览」，确认路线合理
6. 填小车地址、串口、采样参数
7. 点「③ 开始自动采集」，确认后小车开始工作

采集过程中界面会实时显示进度。每个点：静置 3 秒 → 每秒读 1 次共 10 次 → 写入 CSV。

## 三、参数说明

| 参数 | 默认 | 说明 |
|---|---|---|
| 行数 / 列数 | 7 / 9 | 受 `P<行><列>` 两位编号限制，最大 9×9 |
| 房间宽 / 高 | 8.23 / 6.95 m | 用于换算格距和米制坐标 |
| 每点采样次数 | 10 | 次数越多越稳，但耗时线性增加 |
| 静置秒数 | 3 | 到点后等待车身稳定再采样 |
| 速度 | 0.08 m/s | 固件限制 0.03~0.12 |
| X / Y 校准 | 1.0 | 实测后填写 |
| 锁定 SSID | 空 | 填了就会校验，连错路由器立刻停止 |
| 小车地址 | — | `IP:62587` |
| 串口 | COM8 | 只用于读控制密钥 |

## 五、常见问题

**Q：提示"串口上没有读到控制密钥"**
- 确认烧录的是 AutoSurvey 固件（不是旧的 RSSI-only 固件）
- 小车刚上电，没有重启过（密钥每次上电重新生成）
- 串口号选对，别被其他串口工具占用

**Q：连不上小车 IP**
- 电脑和小车必须在同一个局域网
- 先 ping 一下 IP
- 关掉电脑上的 VPN / 代理（脚本已绕过系统代理，但路由可能仍受影响）

**Q：小车走一半停了**
- 固件心跳超时（2 秒没收到心跳）会自动刹停，检查 WiFi 稳定性
- 也可能是底盘报故障（I2C 反馈失败），界面日志会显示原因

**Q：位置越走越偏**
- 麦轮横移打滑是主因，重新校准 X 系数
- 降低速度（0.05~0.06 m/s）能明显改善
- 地面太滑或有坡度时误差会放大

**Q：想改房间尺寸或网格**
- 直接在界面改「房间参数」→ 点「应用网格」，不用重新烧录

**Q：想恢复原来的固件**
```powershell
tools\py.cmd -m esptool --chip esp32 --port COM8 --baud 460800 write-flash 0 backup\flash_esp32_xxxx.bin
```

## 六、安全须知

- 上电默认不运动，必须显式启动
- 运行前清空路线上的杂物，留出车身宽度
- 全程有人看护，能随时切断电源
- 不要在楼梯、桌边等跌落风险区域运行
- 手机 APP 一旦操作小车，自动任务立即退出且不会自动恢复
