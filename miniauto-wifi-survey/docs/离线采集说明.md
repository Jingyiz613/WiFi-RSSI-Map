# 离线自主采集

被测 Wi-Fi 不能联网时，电脑一旦连上它就会断网。离线模式把整套流程改成：

```
电脑 --USB--> 下发任务 --拔线--> 小车自己跑完全程 --插线--> 取回数据
```

中间电脑可以一直连着自己的网（DeepWorks 不掉线），也可以关机带走。

## 和在线模式的区别

| | 在线模式 | 离线模式 |
|---|---|---|
| 控制通道 | Wi-Fi HTTP | USB 串口 |
| 电脑要连被测 Wi-Fi | 是 | **否** |
| 采集中途能否看到进度 | 能 | 拔线后不能 |
| 采集中途能否急停 | 能 | 不能（靠固件自我保护） |
| 需要重新烧录固件 | 否 | **是（一次）** |

> 关键前提：小车必须有电池，拔掉 USB 后仍能运行。如果只能靠 USB 供电，这条方案不成立，只能用在线模式或双网卡。

## 第 1 步：烧录新固件（必须）

旧固件不支持离线指令，必须先烧这一版：

```powershell
cd C:\Users\29193\DeepWorks\miniauto-wifi-survey
powershell -ExecutionPolicy Bypass -File tools\flash.ps1 -Backup
```

看到 `Type FLASH to continue` 输入 `FLASH`。串口自动识别。

烧完后，串口监视器里应该出现：

```
[SURVEY] autonomous mode ready, plan=0 phase=idle
[SURVEY] USB only: SURVEY_BEGIN / SURVEY_STEP / ...
```

## 第 2 步：确认小车连上了被测 Wi-Fi

离线模式不改变 RSSI 的来源：小车仍然要连在被测路由器上。

```powershell
tools\py.cmd host\provision_wifi.py --ssid 被测WiFi名称 --password 密码
```

看到 `已连接：SSID=... RSSI=...` 就行。

> 这一步和以前一样，走 USB，不需要上网。凭据存在小车里，断电不丢。

## 第 3 步：校准（首次必做）

离线模式下也能校准，不需要连被测 Wi-Fi：

```powershell
# 测 X 轴：右移 0.2 m
tools\py.cmd host\survey_offline.py calibrate --axis x --distance 0.2

# 测 Y 轴：前进 0.2 m
tools\py.cmd host\survey_offline.py calibrate --axis y --distance 0.2
```

程序会先下发指令，然后等你按回车才动。回车后小车走一步就停。

用卷尺量实际距离，按这个公式算系数：

```
新系数 = 原系数 × 目标距离 ÷ 实测距离
```

例：命令走 0.9144 m，实测 0.85 m → `1.0 × 0.9144 ÷ 0.85 ≈ 1.076`

算出来的数填到后续命令的 `--x-scale` / `--y-scale`。

> 方向不对（比如该右移却前进）说明小车摆放朝向错了，不是软件问题。把车转 90° 重新摆。

## 第 4 步：下发并启动

先摆好小车：**放在 P11 格子中心，车头朝 P21 方向**（行号增大的方向）。

```powershell
tools\py.cmd host\survey_offline.py run --ap P68 --x-scale 1.076
```

它会做三件事：

1. 规划蛇形路线（路由器格跳过，障碍格绕行）
2. 逐条下发 60~80 步位移到小车（约 2 秒）
3. 发启动指令，立刻返回

看到：

```
SURVEY_STATE,running,0,80,P11,8250
小车已开始按计划行驶。现在可以拔掉 USB（小车靠电池供电）。
```

**这时就可以拔线了。**

## 第 5 步：取回数据

小车跑完会停在最后一个点位。重新插上 USB：

```powershell
tools\py.cmd host\survey_offline.py dump --ap P68
```

输出：

```
小车报告：80/80 步完成，每点 10 次采样
已导出 62 个点，共 620 条采样
输出目录：...\output\AP_P68_20261104_163012
  rss_raw_offline.csv
  rss_summary_offline.csv
  experiment.json
```

`rss_summary_offline.csv` 就是画热力图用的文件，格式和在线模式完全一致。

## 其他命令

```powershell
# 查询当前状态（跑的时候如果 USB 还插着）
tools\py.cmd host\survey_offline.py status

# 立即中止并刹车
tools\py.cmd host\survey_offline.py abort

# 只下发计划，不启动
tools\py.cmd host\survey_offline.py plan --ap P68

# 指定障碍格（路线会绕开，不采样）
tools\py.cmd host\survey_offline.py run --ap P68 --blocked P34 P35
```

## 小车的自我保护

拔线后没有人工干预，所以固件里做了这些兜底：

| 情况 | 行为 |
|---|---|
| 单段移动超时 | 判失败，原地重试 1 次 |
| 连续 2 次移动失败 | 停车，标记 `error` |
| 电机板报故障 | 立即停车 |
| 电池低于 6500 mV | 串口警告，继续跑 |
| 电池低于 6000 mV | 立即停车，保留已采数据 |
| 采集中途断电 | 重启后标记 `aborted`，**已采到的点仍可导出** |

每个点采完就写进 NVS，所以即使中途出事，前面采的数据不会丢。

## 参数限制

| 参数 | 范围 | 说明 |
|---|---|---|
| 速度 | 0.03 ~ 0.12 m/s | 固件硬限制 |
| 单步位移 | 0.05 ~ 1.10 m | 一格约 0.91~0.99 m，刚好够 |
| 步数 | 1 ~ 160 | 62 点约 70~80 步，留了绕行余量 |
| 每点采样 | 1 ~ 32 | 默认 10 |
| 静置 | 0 ~ 30 s | 默认 3 s |

## 常见问题

**Q：`dump` 说"没有采到任何数据"**

小车还没开始跑，或者一启动就报错。先用 `status` 看状态：
- `planned` → 计划下发成功但没启动，重新 `run`
- `error` → 移动失败，检查电量、地面、轮子是否被卡
- `aborted` → 中途断电或中止，已采的数据仍会导出

**Q：跑完发现点位整体偏移**

校准系数不准，或者中途打滑。麦轮横移打滑是物理限制，精度大约 ±5 cm/格。改善办法：
- 降低速度到 0.05 m/s
- 地面清理干净
- 每 10 个点回一次起点做参考（当前固件不支持自动回零，需人工）

**Q：小车跑一半停了，但串口没输出**

拔线状态看不到日志。插回 USB 后执行 `status` 就知道停在哪一步、什么原因。

**Q：能不能一边跑一边看进度**

可以，USB 线别拔。`run` 不加 `--detach` 就会实时打印进度。但线会拖拽，房间 8 米基本不现实。

**Q：中途想叫停**

- USB 插着：`abort` 命令
- USB 拔了：直接按住小车 / 关电源。重新上电后结果标记为 `aborted`，已采数据能导出

## 底层协议（供二次开发）

串口 115200，每行一条 ASCII 命令：

```
SURVEY_BEGIN <speed> <dwell_ms> <samples> <count>
SURVEY_STEP <label> <dx> <dy> [sample]     # sample 省略=1；0 表示只经过不采样
SURVEY_END
SURVEY_RUN
SURVEY_STATUS
SURVEY_ABORT
SURVEY_DUMP
SURVEY_CLEAR
```

回执：

```
SURVEY_ACK,BEGIN,<count>
SURVEY_ACK,STEP,<received>
SURVEY_ACK,END,<count>
SURVEY_STATE,<phase>,<done>,<count>,<label>,<battery_mv>
SURVEY_RESULT,<count>,<done>,<samples>
SURVEY_R,<label>,<dx>,<dy>,<n>,<ok>,<battery_mv>,<rssi...>
SURVEY_DUMP_END
```

`dx` 向右为正，`dy` 向前为正，单位米。方向映射与 HTTP 在线模式完全一致。
