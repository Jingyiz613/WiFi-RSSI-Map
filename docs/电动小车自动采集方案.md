# 电动小车自动采集执行方案

> 目标：替代人工走点，小车驮着 ESP32-C6 采集板按 62 点网格自动走位，
> 每点自动触发「稳定 3s + 采集 10s」，一轮 ≤25 分钟（人工约 50+ 分钟）。
> 关键前提：**房间固定、网格已知、每点动作固定 → 不需要 SLAM**，用"航向推算 + 定点纠偏"即可。

## 1. 总体架构：小车管腿，Mac 管脑

```
┌──────────────┐   HTTP (房间Wi-Fi)   ┌─────────────────────┐
│  Mac 调度脚本 │ ───────────────────► │ 现有 web app (:8000) │
│ orchestrator │  start/next/state    │ /api/collect/*       │
│              │ ◄─────────────────── │ 守护进程采集 CSI      │
└──────┬───────┘                      └─────────────────────┘
       │ TCP/UDP 指令 (goto/ack)
       ▼
┌──────────────┐   独立供电   ┌─────────────────┐
│ 小车运动主控  │             │ ESP32-C6 采集板  │
│ (ESP32/IMU)  │             │ (放车顶支架,     │
│ 差速轮+编码器 │             │  朝向/高度固定)  │
└──────────────┘             └─────────────────┘
```

- **运动主控只执行原子指令**：`GOTO <格号>` → 走到 → 回 `ACK`，出错回 `ERR`。它不知道采集逻辑。
- **Mac 调度脚本是状态机**：发 `GOTO P12` → 等 `ACK` → `POST /api/collect/next` → 轮询 `/api/state` 到该点完成 → 下一点。调试都在 Mac 上做，固件保持极简。
- **采集板不参与运动控制**，独立电池供电（与车电分离，避免电机噪声打到 Wi-Fi 供电），刚性支架固定在车顶。

为什么不让小车自己调采集 API：可以，但没必要——调试窗口在 Mac，比赛现场出问题能 30 秒改完脚本；固件改一次要重新烧录。

## 2. 走位与定位（本方案的核心难点）

已知条件：网格原点 (0.46, 0.50)，间距 0.95 × 0.645 m，9 列 × 7 行，蛇形顺序与现有点序一致。

- **航向**：陀螺仪 Z 轴积分 + 编码器融合。直行用 gyro 闭环纠偏，转弯用 gyro 定量转 90°（不数轮子，轮子会滑）。
- **距离**：编码器里程，走一格（0.95m 或 0.645m）即停。
- **累积漂移是最大风险**：一轮行程 ≈ 65m，1% 漂移 = 65cm，直接跑出网格。对策按成本三选一：
  1. **超声波贴墙纠偏（推荐，≈¥15）**：车侧装 2 个 HC-SR04，每走一格读一次到侧墙距离，与理论值比对修正 y；行尾换行处读到端墙距离修正 x。房间是矩形，天然有两把"尺"。
  2. **起点复位**：每轮回起点物理靠位归零（只解决轮间，不解决轮内）。
  3. **AprilTag / 磁钉地标**：地面贴 3~4 个标记，路过即纠偏（精度最高，要加摄像头/传感器）。
- **容差**：定点误差 ≤±8cm 够用（间距的一半），CSI 对厘米级偏移不敏感。

## 3. 采集一致性保障（血泪教训：P11 偏强 8.3dB 就是朝向/多径问题）

- 采集板**朝向永远对准车头正前方**，刚性支架，不允许晃动。
- 天线区域下方 10cm 内不放金属件/电池；车架尽量用亚克力/尼龙。
- **高度与人工轮次保持一致**（待确认人工采集时板子的高度，建议支架做成 0.8~1.0m 可调，先按人工高度锁定）。
- 到位后先停稳再触发（app 本身有 3s SETTLE，车体振动余量足够）。
- 每轮结束回起点靠位，保证两轮之间起点一致。

## 5. 软件工作项

1. **车端固件**（ESP32，Arduino 框架）：
   - 指令集：`GOTO <格号>` / `TURN <角度>` / `STOP` / `POS?`（回报里程）
   - 状态机：直行 gyro 闭环 → 到距减速 → 停稳 → ACK；超声波异常（<15cm）急停回 ERR
   - 参数整定：轮径/脉冲数标定、gyro 零偏
2. **Mac 调度脚本** `scripts/10_cart_orchestrator.py`（新）：
   - 从 `scripts/layout.json` 生成蛇形格序（与 app 点序一致）
   - 主循环：`GOTO` → 等 ACK → `POST /api/collect/next` → 轮询 `/api/state` → 下一点
   - 断线重连、失败重试 1 次、全程日志；支持 `--dry-run`（只走路不采集，验收走位精度）
3. **web app 无需改动**：现有 `/api/collect/start|next|state` 全部够用。

## 7. 风险与对策

| 风险 | 对策 |
|---|---|
| 里程计漂移超容差 | 超声波贴墙纠偏（已含）；不行升 AprilTag |
| 电机噪声干扰采集板 | 采集板独立充电宝供电；采板期间电机全停（本来就是停稳再采） |
| 车身遮挡/反射改变信道 | 采集板放车顶最高处、天线周边无金属；M5 用人工数据交叉验证，超标就垫高支架 |
| 地面不平/地毯 | 换大直径轮（≥65mm）、降低重心；现场先勘地 |
| 比赛现场 Wi-Fi 环境不同 | 调度脚本参数化（IP/SSID/点位表），现场 10 分钟可改 |
